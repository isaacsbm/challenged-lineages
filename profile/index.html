Application profile

Challenged Lineages Application Profile

Which properties each kind of record uses, which are required, and what their values may be. Dublin Core describes every record; ccv: properties, shown in red, appear only where Dublin Core cannot express something.

Format
DCMI Tabular Application Profile (DC-TAP), compiled to SHACL
Shapes
8 (Dataset: 6 properties, Lineage cluster: 4 properties, Work: 17 properties, Instance: 13 properties, Challenge record: 12 properties, Lineage link: 4 properties, Agent: 4 properties, Location: 4 properties)
Download
tap.csv · namespaces.csv · shapes.ttl

How it works

The profile is written once, as a DC-TAP table (tap.csv), where each row says how one property is used in one kind of record. The build script compiles that table into SHACL shapes (shapes.ttl), so any standard SHACL validator can check the published data against it. Every shape is closed, so a misspelled or stray property is reported as well as a missing one.

To validate the collection yourself with pySHACL, run this from the project folder. The -e option adds the vocabulary, so the validator can confirm that each value is a concept in the right ccv scheme:

pip install pyshacl
pyshacl -s profile/shapes.ttl -e terms/ccv.ttl data/collection.ttl

The pairing rule

Every ccv:challengeLineage link is also stated with the Dublin Core relation that fits its evidence, so a Dublin Core-only application still sees the link. A table can't express a rule that compares two properties, so this one is a SHACL-SPARQL constraint on the Work shape. Instances pair with dcterms:isVersionOf instead.
